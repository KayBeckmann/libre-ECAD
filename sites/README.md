# M8 private information sites

Two static sites, two independent nginx containers, German and English. No runtime
backend, analytics, cookies, external assets or frontend dependencies. Local Noto
fonts are reused with their license. The SVG is actual renderer output from the
synthetic three-phase example, generated by:

```bash
cd backend/ecad_documents
dart run bin/site_sample.dart > ../../sites/assets/drawing.svg
```

## Build and run

From the repository root:

```bash
python3 sites/build.py
python3 -m unittest discover -s sites/tests -v
docker compose -p libre-ecad-sites -f compose.sites.yml up -d --build
```

By default, only loopback ports 8187 (homepage) and 8188 (wiki) are published.
To retain an authorized private LAN configuration, copy `.sites.env.example` to
`.sites.env`, use the **specific private interface address**, and set the three
origins. Then always use the saved configuration:

```bash
docker compose -p libre-ecad-sites --env-file .sites.env -f compose.sites.yml up -d --build
```

Origins are build arguments: rebuild after changing them. They accept HTTP(S)
origins only, without paths, credentials, query or fragment. Empty origins use
browser-side same-host links with standard ports; configured origins also work
without JavaScript. No backend service is a dependency. Either site can be built,
started, stopped or replaced by naming just `homepage` or `wiki`.

The Docker build context uses matching root and Dockerfile-specific allowlists
(the root file also covers the classic builder). Local `.env`,
credentials, Git history and application builds are not sent to this builder.
The optional verified Linux artifact **is** included. Generated output is ignored.
Nginx has a read-only root filesystem with ephemeral runtime directories; no
container volume stores user data. Access logging is disabled. Error logs and
upstream infrastructure may still contain connection information. Security headers
apply to HTML and assets. The sites carry noindex; this is not access control.

## Verified downloads

No manifest means no download link. Do not fabricate a manifest by hand. On Linux,
with Flutter, the native build prerequisites, Xvfb and libX11 installed:

```bash
python3 sites/verify_linux.py
# Or: python3 sites/verify_linux.py --xvfb /absolute/path/to/Xvfb
python3 sites/build.py
```

The verifier checks the app source against `version.json`, refuses changed or
untracked app sources, and runs Flutter analysis, unit/widget tests, native
integration (real encrypted file reopen, editor and PDF with Dart HTTP blocked),
release build and an actual release-window launch on a private virtual display.
It uses a temporary XDG data/config directory and never a real user's vault.
Only then does it package the **whole** Linux bundle, MIT license and source/log
checksums in `sites/artifacts/`. An earlier manifest is removed before checking;
a failed check cannot publish a success manifest. Hash/size/source/check failures
abort the static build. Rebuilding without a manifest removes old download files.

The package is a development build, not a cross-distribution or production
certification. Its host, source and test log are downloadable. Android release
uses debug signing and needs HTTPS; physical-device acceptance is pending.
Windows build/device acceptance is pending. Neither has a download link here.
The download manifest is local operator evidence, **not a signed supply-chain
attestation**. Publishing requires review of the artifact and log.

## Content and translation ownership

- `version.json`: documentation version, date, app source, supported languages,
  responsible reviewer and private publication status. App/source stays pinned
  even when only the documentation changes.
- `content/home.json`: paired homepage and publication-status copy.
- `content/wiki.json`: ordered chapters; stable language-neutral slugs and section
  IDs; paragraphs, notes, lists, code blocks and internal chapter links. All text
  is escaped. Raw HTML is not accepted.
- `assets/site.css`, `site.js`: responsive layout, chapter search, menu and language
  anchor preservation. Search is local to each language/version.

Kay Beckmann owns DE/EN review and publication. Change both translations in one
review for changed claims, commands or limits. The build validates chapter/section
parity and references; it does not certify semantic translation accuracy. Tests
crawl local/cross-container links and anchors in both languages. Stable section
IDs allow language changes to preserve the current section.

M8 is the first documentation version (`/de/m8-dev/<chapter>/`). For a new app
baseline, update the version and app-source pin together, review both languages,
regenerate downloads and run acceptance. Preserve any **published** previous
version through its tagged source and separately served static tree; do not
silently replace old version URLs with new content. This first private preview
has no earlier published versions to migrate.

professional, platform and HA acceptance. Product/name/trademark/domain review,
actual legal/privacy/rental terms and **Kay's explicit publication approval**
remain required. The status page is intentionally not a fabricated legal notice.
